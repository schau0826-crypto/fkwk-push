# 设计说明

fkwk-push 的目标是在 Android 设备上监听系统通知栏已经展示出来的通知内容，并通过 Bark 转发到 iPhone。

## Scope

项目只处理 Android 系统通知里的可见信息，例如：

- notification title
- notification text
- bigText
- MessagingStyle 摘要
- 来源应用包名

项目不做：

- 读取应用私有数据库
- 抓取聊天窗口 UI
- 自动回复
- 解密或绕过目标应用
- 收集分析数据

## Architecture

```text
Android app
  NotificationListenerService
  app allowlist
  keyword blocklist
  priority mapping
  local Room history
  WorkManager retry
        |
        v
Bark API
        |
        v
iPhone Bark notification
```

## Android App

主要模块：

- `NotificationListenerService`：接收系统通知事件
- `RuleEngine`：优先级与规则评估
- `Forwarder`：写入历史、判断屏蔽/暂停策略、发送 Bark
- `BarkClient`：调用 Bark `/push` API
- `Room`：保存通知历史与失败状态
- `DataStore`：保存 Bark 设置、App 选择、关键词屏蔽等配置
- `WorkManager`：网络恢复后补发失败通知
- `Compose UI`：历史、App 选择、设置三页

## Forwarding Rules

转发前会按顺序处理：

1. 全局转发是否开启
2. 来源 App 是否在监听列表中
3. 关键词屏蔽是否命中
4. 是否启用“亮屏且未锁屏时暂停转发”
5. App 单独优先级覆盖
6. Bark 级别映射
7. 发送成功或失败写入历史

被关键词屏蔽或亮屏暂停的通知会保留在历史里，但不会进入网络重试队列。

## Privacy

通知内容会被发送到用户配置的 Bark server。默认可以使用 Bark 官方服务；如果对隐私要求更高，应使用自托管服务。

## Optional Server

`server/` 目录保留可选服务端能力，主要用于：

- 托管 Bark 通知图标
- 提供简单图标上传接口
- 保留旧版 ntfy 自托管配置，供有需要的人参考

普通用户只使用 Bark 官方服务时，不需要部署 `server/`。
